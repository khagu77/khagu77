# 온라인 이슈 보고서 작성 규칙

현대차 온라인 이슈 보고서(.pptx) 작성 기준입니다. 담당자가 정한 규칙이며, 확장프로그램(`report-extension`)이 이 규칙대로 동작합니다.
규칙을 바꾸면 이 문서와 코드(괄호 안 파일)를 함께 고칩니다.

## 하루 작업량
- 엑셀에서 `+` 표시된 게시물만 보고서에 넣는다.
- **삭제된 게시물은 보고서에 넣지 않는다** (요약표·상세 페이지 모두 제외). (`capture.js` DeletedPostError)
- 보통 하루 8~9건, 많을 때 12건 (2페이지 요약표 최소 8칸, 최대 12칸).
- **작성 개수 설정** (작성 전 화면에서): `전체` 체크 → + 글을 차례대로 전부(연번 1부터, 삭제 글은 빼고 이어서).
  체크 해제 → `총 N개 중 K개 작성` + `앞부분 작성 / 뒷부분 작성` 선택. N 은 엑셀을 넣으면 + 표시 개수로 자동 입력.
  - 뒷부분: + 글 중 **뒤에서 K개**를 (N−K+1)~N번으로 작성, 1~(N−K)번은 연번만 있는 빈 칸. 예) + 8개, 8개 중 4개 → 5·6·7·8번째 + 글을 5~8번으로.
  - 앞부분: + 글 중 **앞에서 K개**를 1~K번으로 작성, (K+1)~N번은 연번만 있는 빈 칸.
  - 나머지 + 글은 다른 담당자 몫이라 열지 않음. 번호는 + 글 순서 그대로(삭제 글 자리는 빈 칸). 상세 페이지도 그 번호(No.)로. (`app.js` countPlan, `pptx.js` 번호별 배치)

## 파일
- 파일 이름: `YYMMDD_현대차 온라인 이슈 보고서.pptx` (날짜만 매일 바뀜)
- 저장 위치: 담당자가 설정에서 고른 폴더(예: `현대차_2026_온라인모니터링/2026_오전 보고서/오전보고서_최종파일`)에 바로 저장. 같은 이름이면 덮어씀. 고른 폴더가 없거나 저장 실패 시 다운로드 폴더. (`app.js` saveDir)
- 서식·폰트·안내선은 완성된 보고서(템플릿)를 그대로 따른다. (`pptx.js`)
- 2페이지 요약표: 칸 수(8·10·12개 …)와 상관없이 **표 아래 끝선은 템플릿 표와 같은 위치** — 표 틀 높이에서 머리글 행을 뺀 높이를 데이터 행에 똑같이 나눔. 복제한 행마다 PowerPoint 행 ID(a16:rowId)를 새로 매김(같으면 PowerPoint 에서 표 수정·크기 조절이 안 됨).

## 표 칸
| 칸 | 규칙 |
|---|---|
| 차종 | 엑셀 차종 코드(**B열**). EV/HEV/FCEV 는 제원 칸으로. 매체의 동호회명은 **A열** (`excel.js`) |
| 제원 | 2.5T, 3.5T, 1.6T, 2.0, HEV, EV, LPI 처럼 구체적으로. 게시글에서 확인이 안 되면 **작성자의 계약인증·출고인증 글이나 이전 글**에서 확인·유추해 기입. 아무리 봐도 없으면 `-`. 엑셀 차종에 EV 등이 있거나 전기차 전용 모델이면 그 값 (`capture.js` authorCertPosts, `ai.js` spec) |
| 불만 구분 | 대부분 **주의**. 악성 민원 또는 주요 심각한 이슈는 **경고**, 화재·급발진 등은 **심각**. 해당 단계 글자만 색: 주의 초록 `00B050` / 경고 파랑 `0563C1` / 심각 진한 빨강 `C00000` (`pptx.js` LEVEL_COLORS) |
| 경과 | 거의 항상 **초기** (필요할 때만 진행/타결) |
| 게시글 위치 | 항상 `https://cafe.naver.com/카페주소/글번호` 형식. naver.me 단축 주소도 이 형식으로 바꿔 적음. 게시글의 'URL 복사' 버튼이 주는 주소를 그대로 씀 (`capture.js` copyUrlProbe) |
| 조회수 · 댓글 | 게시글 화면에 보이는 값 |
| 내용 요약 | **반드시 2줄**: 1줄 본문 요약 + 1줄 `댓글 반응 : …`. 첫 줄은 너무 짧게 쓰지 말고 게시글 주요 내용을 풍부하게, 포인트를 잘 잡아 **한 줄(약 75자)을 꽉 채우게 60~72자**(차량 상태 → 상황 → 증상 → 조치 → 요구/불만). 댓글 반응은 60자 이내. 댓글이 없으면 `댓글 반응 없음`. 벗어나면 AI 에 한 번 더 맞춰 달라고 요청 (`ai.js` BODY_MIN, BODY_MAX, REACTION_MAX) |
| 댓글 반응 | 캡처한 댓글 2개를 순서대로 요약. 그대로 옮기지 않고 오탈자·맞춤법을 고쳐 자연스럽게. **댓글 말투를 따름**(존댓말이면 존댓말 — 말 그대로 여론). 각 문장 끝에 **마침표**, 느낌표·물음표 댓글이면 그 기호. **두 댓글 사이에 쉼표**. 형식: `‘…습니다., …하세요!’ 등의 여론` |
| 이슈 신규/중복 | 댓글 중 "저도 그래요 / 나도 그랬다" 뉘앙스 댓글 수 + 같은 게시판 최근 3개월 동일 이슈 게시글 수를 러프하게 더함. 0이면 `신규`, 아니면 `중복 N건`. 대부분 신규 |
| 입고/운행지역 | 작성자 닉네임으로 판단(예: `부산ll○○` → 부산). 모르겠으면 작성자의 작성글 보기에서 확인되면 기입, 아니면 `-` |
| 집중관리고객 | 같은 작성자의 동일 증상 중복 게시글이 있을 때만. 기본 `-` |

## 캡처
- 모든 캡처는 고화질(화면 2배)로 찍고, 슬라이드에 놓이는 크기 기준 **330ppi(기본)** 로 줄인다. 150ppi 는 레티나 화면·확대 시 흐려서 기본값을 올림(담당자 요청). 설정에서 220·150ppi 로 바꿀 수 있음. 크게 줄일 때는 절반씩 단계적으로 고품질 축소. 줄일 때는 **가로세로 비율 유지**(임의로 찌그러뜨리지 않음). 잘라낸 부분은 지움. (`imageproc.js` encodeAtPpi)
- **제목 캡처**: 게시판 이름 · 제목 · 작성자 동그라미 아이콘 · 닉네임 · 작성일·조회수(오른쪽 댓글·URL 복사 포함)를 **한 장**으로. 글 제목 영역(article_header)만 찍고, 글 아래 '○○님의 게시글 더보기' 영역은 섞지 않음. 아이콘이 잘리지 않게 줄 간격은 줄이지 않음. 가로 15cm(높으면 12cm).
- 연한 회색 **기본 프로필 아이콘**도 배경으로 보고 잘라내지 않는다 (`imageproc.js` INK_DIFF). 폭 대부분을 덮는 칸 구분선은 지운다.
- **본문 캡처**: **작성자가 쓴 본문만.** 카페 게시판 글쓰기 양식으로 본문 맨 위에 자동으로 들어가는 운영 안내(예: 아이오닉9 오너스 자유게시판의 "📍 함께하는 … 카페 / 질문은 질문 답변 게시판 … / 카페 활동 예의 … ____")는 캡처·요약에서 뺀다. 화면에 보이는 **줄 단위**로 판단(안내 문구와 본문이 한 글 상자·한 문단 안에서 줄바꿈으로만 이어져 있는 경우가 많음). 안내 줄의 글자만 가리고, 안내만 든 상자는 밑줄·테두리까지 통째로 가림. 아이오닉9 오너스 공통 문구는 미리 등록(`SEED_BOILERPLATES`, 띄어쓰기·이모지 무시하고 글자만 비교). 맨 앞부터 이어지는 '운영 안내 말(카페·게시판·등업·예의·회칙·탈퇴·작성해주세요 등)' 구간과 **빈 질문 양식**("1. 구동방식: 2. 인승: 3. 색상: …" 처럼 값이 비어 있는 항목)을 마지막 구분선(`____` 밑줄 문단·가로줄)까지 뺀다. 구분선이 없으면 맨 앞 안내 문단들만. 양식에 값을 채운 줄(예: "구동방식: AWD")은 작성자 정보라 남긴다. 한 번 찾은 문구는 기억해 다음 글에서도 뺀다 (`capture.js` boilerplate).
- 본문 첨부 이미지는 가리고 글자만. 빈 줄은 없애되 **줄 간격은 원래 글의 자연스러운 간격**(글자 높이의 약 절반)으로 — 너무 빡빡하게 붙이지 않음. 원본의 51%(넘치면 46%), 4.56cm 안내선부터.
- **본문은 끝까지 모두 캡처** (중간에 끊기면 안 됨): 본문 캡처 때 사진·영상·안내 문구는 자리까지 없애 글자만 잇고, 길면 여러 번(3000px씩) 나눠 찍어 이어 붙임(최대 16000px) (`capture.js` BODY_CHUNK).
- **본문이 아주 길면 여러 단으로**: 46%로도 안 들어가면 댓글을 줄이거나 자르기 전에, 줄 경계에서 높이가 비슷하게 나눠 **왼쪽·오른쪽 두 단**으로 나란히(각 단은 글자 끝에서 오른쪽 여백을 자름) — 담당자 예시(allfm01/2161564)처럼. 두 단이 안내선(4.56~18.66cm, 댓글 위) 안에 들어가도록 필요하면 글자를 조금 줄임(최소 36%), 그래도 안 되면 세 단(최소 30%). 한 줄이 너무 길어 안 되면 예전처럼(댓글 줄이기 → 아래 자르기) (`layout.js` splitBody)
- **본문 글이 없는 글(영상·사진만)**: 본문 자리가 비지 않게 **가로로 긴 영상·사진을 본문 자리**(4.56~18.66cm, 제목 아래·댓글 위)에 같은 폭으로 한 줄에 1~3개(가장 크게 들어가는 개수). **세로 영상·사진은 원래대로 오른쪽 영역**. 담당자 예시(corbyphone/189064: 가로 영상 2개를 본문 자리에 나란히) (`layout.js` layoutBodyMedia)
- **본문 첨부 사진·영상**: 사진은 화면 캡처 대신 원본 이미지 파일을 받아 씀(흐린 미리보기 방지). **영상은 플레이어 화면(첫 화면·재생 버튼·재생 시간·제목 줄)을 캡처**해 사진처럼 함께 넣음. 글에 나온 순서대로. 오른쪽 영역(19.86~25.66cm).
  - **가로로 긴 사진·영상은 모두 같은 폭**(영역 전체 5.8cm)으로 한 줄씩, 세로로 긴 것은 같은 폭으로 두 개씩 나란히. 넘치면 위(5.93cm)까지 확장하고, 그래도 넘치면 전체를 같은 비율로 줄임 — 그림마다 폭이 들쭉날쭉하지 않게 (`layout.js` layoutImagesUniform)
- **댓글 캡처**: **2개**. 자극적이거나 심각하다고 느껴지는, 길지 않은 댓글 위주.
  - 작성자 동그라미 아이콘, 오른쪽 하트·`…` 버튼까지 잘리지 않게 함께 캡처.
  - **게시글 작성자의 댓글은 쓰지 않음.** **대댓글도 쓰지 않음.**
  - 이모티콘(스티커) 댓글은 되도록 쓰지 않음. 그것밖에 없으면 이모티콘을 지우고 작성일시를 댓글 내용 바로 밑에 붙여서 사용.
  - 본문과 같은 배율, 아래 안내선(17.13cm)에 맞춤.

## 문장 표현 (작성 가이드)
- **"내비"·"네비" 금지 → 무조건 "내비게이션"** (작성자가 내비·네비라고 썼어도). 요약 등 모든 문구. AI 지시 + 결과 자동 교정 (`ai.js` fixWording)
- **"계기판" 금지 → 무조건 "계기반"** (작성자가 계기판이라고 썼어도). AI 지시 + 자동 교정
- **"~으나" 뒤에는 반드시 쉼표**: "점등되어 하이테크센터에서 수리받았으나, 안내 미흡", "발생해 부품 교체했으나, 시트 소음 지속". AI 지시 + 자동 교정
- **"돼"·"됐" 줄임 표현 금지 → "되어"·"되었"으로 풀어 씀** (확인돼 → 확인되어, 점등됐다며 → 점등되었다며). 제목·요약표·본문 요약에 자동 교정 (댓글 반응은 댓글 말투를 따름)
- **2페이지 요약표 '내용 요약'**: 구구절절한 설명·미사여구 없이 깔끔하게 **키워드 중심 명사형**. 담당자 수정 예) "타이어 공기압 경고등 및 도장·루프 필러 조립 불량", "라디에이터 캡 냉각수 누수", "HUD 부품 결품으로 2개월 수리 지연", "테일게이트 부위 부식 발생", "시동 시 내비게이션 디스플레이 불량 발생"
- 본문 요약 끝맺음은 **다양하게 섞는다** (모두 "~하는 내용"으로 끝내지 않음): "~의 불만글 게재", "~ 동일 증상 여부 및 해결 방안 문의", "~ 증상 관련 사진과 함께 글 게재", "~며 품질에 대해 불만 토로", "~ 정비 후기 공유", "~며 증상에 대해 문의하는 내용" 등. 같은 보고서의 앞 글과 겹치지 않게 (`ai.js` recentBodies)
- 현상만 간결한 보고체. 자극적 표현은 순화. "에러", "결함" 금지 → 증상/현상/오류/불량.
- 시작: "최근 출고한 차량에서", "주행 중에", "차량의 ○○ 부분에서" / 끝: "~며 증상에 대해 문의하는 내용", "~며 품질에 대해 불만 토로하는 내용", "~며 공유하는 내용".
